OpenJev-Fast

6× Faster Open‑Jev‑27B Inference with Specialized CUDA Kernels

Fused CUDA kernels, shared-prefix execution, tuned GEMMs, and CUDA Graphs on a single NVIDIA B300.

Yiqi Lyu
Northwestern University
Advised by Zhaoran Wang
Code Report

The 231 public JevBench tasks sent one after another to each server on the same GPU, replayed at real speed from the measured per-task latencies (HTTP, both servers warmed up).

TL;DR

An inference backend for Open-Jev[1]. It runs locally, keeps the model and the request format of Open-Jev's local server, and replaces the forward pass with fused CUDA kernels, a prefix tree that computes shared prompt text once, and CUDA Graphs.

How it works

1

Fused CUDA kernels

Hand-written kernels replace every non-matmul op in a layer. Kernels per request drop from ~5000 to 642, and the CPU launch bottleneck goes away.

2

Two-level prefix tree

The shared context is computed once, each question once, and each candidate only its tail, all in one packed forward pass.

3

Gated DeltaNet and attention kernels

The linear-attention recurrence and the tree-masked attention run in our own kernels (mma.sync, ldmatrix, cp.async in inline PTX): 74 → 36.5 µs and 21.4 → 12.7 µs per layer.

4

Tuned GEMMs + CUDA Graphs

Merged weights, split-K with fp32 partial sums, per-shape cuBLASLt algorithms, and one CUDA Graph per request shape.

Prefix tree for the example request. Linear-attention layers still run each candidate over its full path, so results match the original; full-attention layers use an ancestor mask.

Correctness

  • 98–100% of the element-wise kernels' outputs are bit-identical to the PyTorch/FLA reference; the Gated DeltaNet and attention kernels match FLA and cuDNN within bf16 rounding (relative L2 about 10⁻³).
  • On the example request, probabilities differ from the original by at most 0.0082 (the two original paths, with and without FLA, differ by 0.0087 from each other); on a 10,722-token request by 0.019. Decisions are unchanged.
  • On JevBench, accuracy changes by one task: one near-tie prediction changed (original: 0.504 vs 0.496).

Setup and limits

  • Latency is the forward pass plus scoring head for the example request, with prompts tokenized beforehand. All three numbers use the same script: median of 30 runs after 5 warm-ups.
  • Tested only on an NVIDIA B300. Needs about 98 GiB of GPU memory.
  • bf16 only; one request at a time; a new request shape adds 1–3 s once, for graph capture.
